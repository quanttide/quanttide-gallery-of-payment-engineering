# 代金券：从无台账的发放到可对账的记录

组织以代金券给成员的行为与成果定价，而发放本身只留一句话：给谁、多少、为什么。没有编号、没有逐笔回执，于是三件事无从核对：谁拿过、同一个人拿过几次、账上是否都有。本案例按需求、意图、规格三段，记录这件事的一般做法。

## 需求

### 情境

代金券是内部定价工具，发放有两种走法——按既定制度由公司方直接发，或由管理者按政策需求当场发。两种走法留下的都只是一句发放话：接收人、金额、事由。

要做的是把这些零散语句收敛成一份可对账的记录：每个事实有唯一指认，合计可互校，无法核对的照实留着。约束三条——只记真实发生过的发放，不补录不臆测；金额以原文为准；记录可对外复用时不得带身份细节。

### 难点

**发放与讨论混在一起。** 定价说明、他人提请、政策公布、事后答疑都带金额、都带「券」字，但它们不是发放。判据只有一条：接收人、金额、事由同时出现才算一笔。

**金额是组合表述。** 「主额 500 加追加 500 共 1000」这类说法里，按整句记会漏追加，按字面相加会把「共」重复计入。必须分主额与追加两段拆，合计取分段之和。

**只有凭证，没有账。** 无编号、无回执、无核销凭据，任何「合计多少」的说法都只能靠发放原文自证。

**政策与发放不是一对一。** 一句「首个项目按 1000 来发」是预算口径，不对应任何具体发放。两者混记，记录就退化成预算表。

## 意图

### 自然语言规则

1. **三要素判一笔**：接收人、金额、事由同时出现才算一次发放；讨论、提请、政策、答疑四类不进记录。
2. **金额照原文**：主额与追加分段拆分，合计取分段之和，不采信口头的「共多少」。
3. **编号先立**：日期加序号，一笔一号，给每笔券唯一指认。
4. **只记已发出的券**：政策与预算口径不入账，留作待办。
5. **两数互校**：合计必须等于按接收人汇总之和，不等即回查。
6. **缺口照实**：无回执、未核销、口径未定一律写进交付物，不为凑整删改。
7. **对外去身份**：记录复用到公开场合时，人名换角色、去可定位标识，金额与事由等业务数据保留。

### 形式化规则

```text
对象：原始凭证集合 M，候选集合 C，发放集合 P，记录集合 R

前置条件
  M 为一个观察窗口内的全部发放相关原文，含截止时点
  P ⊆ C ⊆ M

操作
  collect(W)    取窗口内原文，登记截止时点
  locate(C)     按三要素判定发放，得到 P
  record(P)     一笔一条记录，编号为日期加序号
  reconcile(R)  合计与按接收人汇总互校
  mask(R)       对外复用时，人名换角色、去可定位标识

不变式（记录交付时必须全部成立）
  I1 可回溯：R 中每条都能指回 M 中的一条原文
  I2 互斥：讨论、提请、政策、答疑四类不进 P
  I3 对账：合计 = 按接收人汇总之和
  I4 缺口：无法对账的条目照实保留
  I5 去身份：对外版本无姓名、无定位标识，业务数据完整
```

## 规格

### 自然语言描述

四步，每步以前一步产出为输入，以可核对的结果收尾：

1. **取数**：圈定观察窗口，取窗口内全部发放相关原文，登记截止时点；产出＝原文清单，覆盖完整或缺口已标明。
2. **判定**：按三要素逐笔判，讨论、提请、政策、答疑四类剔除，组合金额拆主额与追加；产出＝发放清单与逐笔金额明细。带金额的提请与政策原文和发放长得一样，这一步不宜全交机器。
3. **落账**：一笔一条记录，字段为编号、时间、接收人、金额、事由、发放人、凭据位置；合计与按接收人汇总互校；产出＝内部版记录。
4. **核销**：把每笔券对到兑现凭据上，回答「这笔券兑现了什么」。这一步是记录的最后一环，也是当前最大的缺口。

### YAML 描述

```yaml
取数:
  窗口: 观察起止时间，写入记录
  范围: 窗口内全部发放相关原文

步骤:
  - 从: 原始凭证
    到: 候选清单
    执行者: 系统
    动作:
      纳入: 出现券、奖励、发放一类字样的原文
      留痕: 登记截止时点与条数
    判据: 覆盖完整，或缺口已标明

  - 从: 候选清单
    到: 发放清单
    执行者: 系统给候选，人逐笔判
    动作:
      保留: 接收人、金额、事由同时出现
      剔除: [定价说明, 他人提请, 政策公布, 事后答疑]
      拆分: 主额与追加分段，合计取分段之和
    判据: 无凭据的条目已打缺口标记

  - 从: 发放清单
    到: 内部版记录
    执行者: 系统
    动作:
      字段: [编号, 时间, 接收人, 金额, 事由, 发放人, 凭据位置]
      编号: 日期加序号，一笔一号
      互校: 合计 = 按接收人汇总之和
    判据: 两数相等，不等即回查

  - 从: 内部版记录
    到: 对外可复用版本
    执行者: 系统执行，人复核
    动作:
      换: 人名 → 角色
      删: 可定位标识
      留: 金额、日期、事由、角色关系、缺口条目
    判据: 无姓名、无定位标识

校验:
  可回溯: 每条记录可指回具体原文
  互斥: 四类非发放原文未混入
  对账: 合计等于按接收人汇总之和
  缺口: 无回执条目照实保留
```

## 结果与缺口

一个两个月余的窗口里判出十余笔发放、合计数千元，发放入期内只涉及少数成员；按事由分，课题与评审占多数，教学与交流次之，文书与决议、问答激励零星若干；单人最多也仅为数笔、合计数百元。

缺口四条：仅少数有账本回执；组合金额漏拆即错记；政策口径与具体发放存在一对多，不能倒推；核销未对接兑现凭据。

发放流程仍有断裂：券发出后无人确认到账，核销也没有回执路径。三件待办已经立下——固定编号、补齐逐笔回执、核销接上兑现凭据。这三件落地之前，代金券只能算「可核对的记录」，还谈不上「可审计的账」。
