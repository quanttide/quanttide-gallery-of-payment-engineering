# 代金券：从无台账的发放到可对账的记录

组织以代金券给成员的行为与成果定价，而发放这个动作本身只留一条群消息。没有编号、没有逐笔账本回执，于是三件事长期无从核对：谁拿过、同一个人拿过几次、账上是否都有。本案例按需求、意图、规格三段记录这件事怎么被收拾出来。

## 需求

### 情境

代金券是内部定价工具：成员完成课题、通过评审、参与教学与答疑，由公司方按制度发券。发放有两种走法——按既定制度由公司方直接发，或由管理者按政策需求在群内公开发。两种走法都只留一句群消息，形式上就是「某人 + 金额 + 事由」。

要做的事是把这些发放消息收敛成一份可对账的记录：入口是群聊原文，出口是带编号、合计与缺口说明的发放表。约束四条——单源取数，不补录不臆测；关键词检索与全量扫描两路必须收敛；金额以原文为准、组合表述按明细拆；出群前人员与链接换角色与位置。

取数窗口为两个月余的群消息，全量数千条，其中与券相关的数十条。当中只有一条注明「计入账本」，其余没有账本回执。

### 难点

**发放与讨论混在一起。** 制度定价、他人提请、政策公布、事后答疑都带金额、都带「券」字，但它们不是发放。

**同一件事有多种写法。** 券在群里有「代金券」「优惠券」「券」三种写法，只用一种会漏，用最宽的那种会带进无关票券。

**金额是组合表述。** 「主额 500 加追加 500 共 1000」「追加 2 张 100」都出现过。按整句记会漏追加，按字面相加会把「共」重复计入。

**只有消息，没有账。** 无编号、无回执、无核销凭据，任何「合计多少」的说法都只能靠消息原文自证。

## 意图

### 自然语言规则

1. **单源取数**：只以该群消息为数据源，不跨群、不补录。
2. **并集检索**：关键词至少覆盖「代金券」「券」「奖励」「发券」，取并集而非任一单查。
3. **双路收敛**：再拉全量逐条匹配交叉验证，两路不一致以全量为准，并把差异原因记进缺口。
4. **三要素判发放**：同一条消息内同时给出接收人、金额、事由才算发放；讨论、提请、政策、答疑四类一律不进记录。
5. **金额照原文**：主额与追加分段拆分，合计取分段之和，不采信口头的「共多少」。
6. **编号先立**：`YYYYMMDD-NN`，当天第几笔给到第几号，每笔券有唯一指认。这一条来自群内成员自己的提议。
7. **只收已发出的券**：政策与预算口径（如「首个众包项目按 1000 来发」而无对应发放消息）不进记录，留作待办。
8. **缺口照实**：无回执、无核销、口径未定一律写进交付物，不为凑整删改。

### 形式化规则

```text
对象：群消息集合 M，候选集合 C，发放集合 P，记录集合 R

前置条件
  M 为该群的群内全量消息，含取数截止时间
  P ⊆ C ⊆ M

操作
  collect(G)   取数，登记截止时间
  filter(M)    关键词并集 + 全量逐条匹配，两路交叉
  locate(C)    按三要素判定发放，得到 P
  record(P)    一条一条落记录，编号为日期加序号
  mask(R)      人员换角色、链接与标识清零，业务数据保留

不变式（记录交付时必须全部成立）
  I1 单源：R 中每条都能回溯到 M 中的一个消息位置
  I2 收敛：关键词并集结果 = 全量匹配结果，否则以全量为准并记缺口
  I3 互斥：讨论、提请、政策、答疑四类不进 P
  I4 对账：合计 = 按接收人汇总之和
  I5 缺口：无法对账的条目照实保留
  I6 脱敏：R 中无人员姓名、无群标识与链接
```

## 规格

### 自然语言描述

四步，每步以前一步产出为输入，以可核对的结果收尾：

1. **取数**：按群名定位唯一数据源，关键词并集检索后再拉全量交叉；产出＝候选消息清单，两路条数一致或差异可解释。
2. **判定**：按三要素逐条判，讨论、提请、政策、答疑四类剔除，组合金额拆主额与追加；产出＝发放消息清单与逐条金额明细。机器只把候选收窄，逐条由人过——带金额的提请和政策消息长得和发放一样。
3. **落账**：一条发放消息一条记录，字段为编号、时间、接收人、金额、事由、发放人、消息位置；文末给合计与按接收人汇总，两者互校；产出＝内部版记录。
4. **核销**：把每笔券对到参会记录与报名记录上，回答「这笔券兑现了什么」。这一步尚未打通，是目前最大的缺口。

### YAML 描述

```yaml
取数:
  源: 该群群消息，全流程唯一数据源
  截止: 取数时点，写入记录

步骤:
  - 从: 群消息
    到: 候选消息清单
    执行者: 系统
    动作:
      检索: ["代金券", "券", "奖励", "发券"]
      全量匹配: ["券", "奖励", "奖金"]
      合并: 取并集，两路比对
    判据: 两路条数一致，或差异原因已记录

  - 从: 候选消息清单
    到: 发放消息清单
    执行者: 系统给候选，人逐条判
    动作:
      保留: 同一条消息内同时给出接收人、金额、事由
      剔除: [制度与定价说明, 他人提请, 政策公布, 发放后答疑]
      拆分: 主额与追加分段，合计取分段之和
    判据: 无对账凭据的条目已打缺口标记

  - 从: 发放消息清单
    到: 内部版记录
    执行者: 系统
    动作:
      字段: [编号, 时间, 接收人, 金额, 事由, 发放人, 消息位置]
      编号: 日期加序号
      互校: 合计 = 按接收人汇总之和
    判据: 两个数相等，不等即回查

  - 从: 内部版记录
    到: 可公开记录
    执行者: 系统执行，人复核
    动作:
      换: 人名 → 角色，机构名 → 类型名
      删: 群标识、消息链接
      留: 金额、日期、事由、角色关系、缺口条目
    判据: 全文无姓名、无群标识与链接

校验:
  单源: 每条记录可回溯到具体消息位置
  收敛: 关键词并集与全量匹配条数一致
  对账: 合计等于按接收人汇总之和
  缺口: 无回执条目照实保留
```

## 结果与缺口

窗口内判出十余笔发放、合计数千元，发放入期内只涉及少数成员；按事由分，课题与评审占多数，教学与群内交流次之，文书与决议、问答激励零星若干；按接收人汇总，拿得最多的也仅为数笔、合计数百元。

缺口四条：仅少数有账本回执；组合金额漏拆即错记；政策口径与具体发放存在一对多，不能倒推；核销未对接参会与报名记录。

发放流程仍有断裂：券发出后无人确认到账，核销也没有回执路径。三个待办已经立下——固定编号、补齐逐笔回执、核销对接参会与报名记录。这三件落地之前，代金券只能算「可核对的记录」，还谈不上「可审计的账」。
